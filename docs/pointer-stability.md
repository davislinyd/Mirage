# 游標穩定化方案

2026-10-03。規劃，尚未改程式。目標是用現有的 Apple Vision 二維關節點，不接外接設備、不用 z 座標，把游標抖動壓下來，並讓速度門檻跟著手的大小與離鏡頭距離走。

## 為什麼不做深度、不換硬體

- 內建鏡頭做手部追蹤夠用。靜止與移動的食指偵測率 > 95%，點擊錄影 10/10。瓶頸是深度，不是關節點本身。
- 2.5D（關節前縮與掌寬）與 MediaPipe 3D 已評估，訊雜比低於 2D：按鍵 2.1× 對 5.8×，往前戳 1.3–2.0×。不再接。
- 眼動不可行。看完整個螢幕，瞳孔只動約 5 px，Vision 瞳孔點逐幀晃 0.7–2 px。內建螢幕 p50 395–580 pt，通過線是 250。MediaPipe 虹膜最好 p50 531，ptgaze 內建 395。訊號小於雜訊，換模型也救不了。
- Ultraleap Leap Motion Controller 2 能做次毫米手部追蹤，但已停產、要外接，不納入本方案。
- iPhone TrueDepth 是臉部用的紅外深度，手在畫面邊緣時深度會跳，而且 Mac 拿不到。

深度不當絕對量。用掌寬當相對參考：手越近，掌寬占畫面比例越大。

## 與現行 Mirage 的差別

| 項目 | 現在 | 方案 |
| --- | --- | --- |
| 游標跟隨 | 食指 PIP（第二關節） | 食指指尖 |
| 校準 | 伸食指畫圈約 4 秒，學映射 | 同一段畫圈，另外量掌寬 |
| 平滑 | 慢移少動、快移恢復的自訂邏輯 | EMA α = 0.7，死區 2 pt |
| 速度門檻 | 掌寬/秒，掌寬來自校準範圍 | 同單位，但掌寬改為啟動後前 30 幀中位數 |
| 深度 | 不用 | 仍不用。手高度偏離基準 ±20% 就暫停追蹤 |

PIP 的好處是懸空輕抖不會動游標。代價是彎曲時關節前後移約 5–10 mm，投影約 30–60 px。指尖是末端，路徑較直，漂移 < 2 mm（約 < 12 px）。點擊邏輯不改：仍是指尖彎下去再伸直，落點在開始彎之前的位置。

## 四項改動

### 1. 掌寬自校準

畫圈校準期間記錄手腕到小指根的像素距離。取啟動後前 30 幀的中位數當基準掌寬，不要單幀。

所有速度門檻（甩動往上 6、往下 8 掌寬/秒，三指滑動掌心 ≥ 4–5 掌寬/秒）繼續用掌寬/秒，但分母改用這個中位數。手變大、靠近鏡頭時門檻自動跟著走。

量測誤差目標 < ±3%。模擬：±5% 時速度門檻誤判率約 5%，±10% 時約 10%。壓到 3% 以內，誤判低於 3%。

### 2. 游標改跟指尖

只換追蹤點。點擊、拖曳、扳機、甩動、三指、捏合的判定不改。

### 3. EMA 與死區

對游標座標做指數移動平均：

```
y = 0.7 * x + 0.3 * y_prev
```

死區 2 pt：與上一幀輸出差小於 2 pt 就不動。死區不增加延遲。

α 的取捨（模擬，30 fps，階躍到 90%）：

| α | 階躍 90% | 抖動 |
| --- | --- | --- |
| 0.3 | 約 200 ms | 最穩，但超過延遲預算 |
| 0.5 | 約 100 ms | 中間，仍超過 p95 < 50 ms |
| 0.7 | 約 33 ms | 唯一貼近延遲目標的選擇 |

加上推理約 20 ms，α = 0.7 的總延遲 p95 約 58 ms，貼著現有 50 ms 目標。α = 0.5 不合格。

死區不是主力。指尖加 EMA 0.5 之後，約 83% 的幀已經在 2 pt 以內；死區只清殘餘小抖。

模擬結果（raw PIP 含彎曲漂移，逐幀跳動 p95）：

- raw PIP：8.8 pt
- 指尖、無漂移：5.0 pt
- 指尖 + EMA 0.7 + 死區 2：約 4 pt，改善約五成

現有濾波後 p95 < 3 pt 的指標會放寬到約 4 pt。這是為了守住延遲。

### 4. 互動區

啟動時記下手的高度（對應基準掌寬的距離）。之後手偏離這個高度超過 ±20% 就暫停游標追蹤，不重置校準。回到範圍再繼續。避免手忽近忽遠把映射打歪。

## 參數

全部進 `UserDefaults`，設定裡可調。

| 鍵 | 預設 |
| --- | --- |
| emaAlpha | 0.7 |
| deadzonePt | 2 |
| palmSampleFrames | 30 |
| heightTolerance | 0.20 |

## 約束

- 不加 MediaPipe，不接外接硬體。
- 不用 z 座標或深度估計。
- 手勢判定與門檻結構保留，只把速度單位正規化到新的掌寬。
- 保留 30 fps；待命每 3 幀處理一次（約 10 fps）。待命改成 30 fps 大約多 450 mW，不值得。

## 驗證

用現有 `recordings/` 重播。不能退步的基準：

- 點擊 10/10
- 捏合 ≥ 25/26
- 上甩 28/31、下甩 28/28，反向捲動仍為 0
- 日常階段誤觸發仍為 0

新指標：

- 逐幀跳動 p95 < 4 pt
- 濾波延遲 < 30 ms
- 階躍響應 90% < 50 ms（含推理則貼著 58 ms，超過就記下來，不要暗暗放寬）
- 速度門檻誤判率 < 3%

## 不達標時先動哪個

1. 跳動仍 > 4 pt：先把死區改 3 pt，不要先降 α。降到 0.5 延遲會到約 100 ms。
2. 延遲超過 50 ms：α 改 0.8，接受跳動回升。
3. 甩動漏抓或誤觸：先查掌寬中位數是不是只用了少於 30 幀。不要先改 6 / 8 這兩個門檻。
4. 指尖比 PIP 更抖：回退追蹤點，保留掌寬與 EMA。PIP 彎曲漂移是這次換點的理由，不是必須。
