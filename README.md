# Mirage

在 MacBook 鏡頭前以單手手勢操控游標、點擊、捲動與縮放的 macOS App（macOS 26+）。

## 敲兩下掌托：開關 Mirage

在觸控板右邊的掌托用指尖敲兩下（像敲門），效果同 ⌃⌥⌘M，切換啟用與停用。停用時鏡頭關閉，但加速度計還在讀，所以敲得回來；螢幕鎖定、睡眠時不切換。

- **硬體需求**：M1 Pro 以後的 Apple Silicon MacBook。
  - 機身的 IMU（Bosch BMI286）由 SPU 管理，沒有公開 API。
  - Mirage 用 IOKit 直接開 `AppleSPUHIDDevice`（vendor page 0xFF00、usage 3），以 200 Hz 讀取，不需要 root。
  - 讀不到時只記錄，快捷鍵照常。macOS 更新可能讓這個做法失效。
- **選單列選單可以調**：
  - 敲擊力道：衝擊門檻 0.03–0.12 g，預設 0.05。往「輕」越敏感；0.04 以下沒有錄影驗證。
  - 兩下最長間隔：0.3–1.0 秒，預設 0.5。往「慢」可以敲得從容一點。
  - 最短間隔固定 0.19 秒：更快的兩下和用力敲一下的餘振分不出來。
  - 設定存在 UserDefaults，重開後保留。
  - 選單也顯示 Mirage 的 CPU：選單開著時每秒更新，一個核心為 100%，同活動監視器。
- **限制**：
  - 只有一個加速度計，分不出敲左邊或右邊。
  - 在桌上用力敲兩下也會觸發。
  - 敲完約 0.3 秒才切換：要確認沒有第三下。
- **錄影**：`swift run -c release mirage-spike knock`。
  - 只在終端機提示，不開鏡頭。
  - 先結束 Mirage：兩者會互相改加速度計的取樣率。
  - `--check` 只讀 2 秒，印出取樣率與靜止時的加速度。
- **兩份錄影的重播結果**（200 Hz 與 800 Hz 相同）：
  - 一般力道：右側 9/9、左側 10/10。
  - 輕敲：右側 10/10、左側 10/10。
  - 只敲一下、敲桌子一下、打字、用觸控板、開合螢幕：都沒有觸發。
  - 兩份都參與了調參，還沒用新錄影驗證。
- 每個門檻的數據與理由在 `KnockDetector` 與 devlog。

## 三指揮動：換桌面與 Mission Control

控制中時，食指、中指、無名指伸直、小指收起，游標停住（HUD 顯示「三指揮動」）。手掌快速一揮，同觸控板的三指滑動；往上揮是抬手的同時伸出三指也可以：

| 手的動作（你看自己的手） | 送出 | 效果 |
|---|---|---|
| 往右快速一揮 | ⌃← | 到左邊的桌面 |
| 往左快速一揮 | ⌃→ | 到右邊的桌面 |
| 往上快速一揮 | ⌃↑ | Mission Control |
| 往下、慢慢收回 | 不送 | 視為回程 |

- 慢慢移動、斜著揮都不算；一揮只換一個桌面，連續換桌面要一下一下揮；換方向要先停約 0.5 秒，才不會把很快收回來的動作當成反方向的揮動。
- 兩指是捲動，兩指捲動中伸出無名指就切換成三指，捲動結束；收回中指與無名指（只留食指）就回到游標。
- 前提：系統設定 → 鍵盤 → 鍵盤快速鍵 → Mission Control 的「向左／向右移動一個空間」與「Mission Control」要開著（預設就是 ⌃←、⌃→、⌃↑）；換桌面要有兩個以上的桌面。
- 送鍵：只在方向鍵事件加 ⌃ 旗標時系統沒反應，要同實體鍵盤：先送 Control 按下、方向鍵帶 fn 旗標、最後送 Control 放開。實機確認過左右換桌面會切換，⌃↑ 會開 Mission Control。
- 門檻用兩份 `desktop` 錄影（2026-10-01）定，還沒用第三份驗證。手掌中心的速度（三幀頭尾）：往左、往右揮 ≥ 5.0、往上揮 ≥ 4.0 掌寬/秒；三指連續兩幀就算，離開三指 0.3 秒內仍算（揮得快時無名指常常先收起來）。重播（第一份／第二份）：往右揮 6/10、15 下（第二份揮了約 14 下）、往左 7/10、7/12、往上 5/10、7/13；往下、兩指甩動、兩指扳機、日常、移動都是 0 次，要求慢慢移動的階段誤觸 0 次與 3 次。
- 刻意的一揮和快一點的移動用速度分不開：第二份「慢慢移動」階段（約 1.5 個掌寬、0.4–0.5 秒）峰值最高到 5.9 掌寬/秒，刻意的一揮 3.5–9.8。門檻越低抓得越多、誤觸也越多：往左右 4.5 時那個階段誤觸 6 次，6.0 時 0 次、但往左右各少抓 2–4 下。往上揮最難抓：抬手比左右揮慢，又是抬手的途中才伸出三指。既有 `controls` 錄影中，三指姿勢和兩指姿勢分得開（兩指階段 0 幀誤判成三指）；日常階段 10201 幀中有 154 幀（1.5%）是三指姿勢，連續 0.15 秒以上的有 5 段（0.17–0.4 秒），所以要停留 0.3 秒。錄影用 `swift run -c release mirage-spike desktop`。

## 五指捏合：縮到 Dock（⌘M）

- 控制中張開手掌停一下（約 0.2 秒），再把五指尖往中間收攏捏成一點，送一次 ⌘M，把目前視窗縮到 Dock。要再送一次，先張開手。
- 握拳不算：握拳時指尖收到指根下方，拇指壓在食指上，不會碰到中指尖。待命時的喚醒手勢（張手 → 握拳）不受影響；待命時捏合也不送。
- 三份錄影共 26 下捏合抓到 25 下（漏掉的一下拇指沒碰到中指），握拳、兩指扳機、日常都沒有觸發。錄影：`swift run -c release mirage-spike gather`（五指捏合、張手 → 握拳、兩指扳機、日常）。

## M3：操作者鎖定、縮放與狀態面板

- 操作者鎖定：喚醒後只跟著喚醒的那隻手，依連續性判斷（每一幀取離上一幀最近、2.5 個掌寬以內的手）。旁人的手或自己的另一隻手在畫面別處出現都不影響；操作者的手離開超過 2 秒就停止控制，要重新喚醒。
- 縮放：扳機按住不放約 0.5 秒，游標停住；之後手往上移放大、往下移縮小，每移約 150 pt 送一次 ⌘= 或 ⌘−（瀏覽器、Finder、預覽程式等都適用）。放開拇指就結束，不會送右鍵。
- 右鍵改成拇指抬起時才送出，按住超過 0.5 秒就是縮放。一般的扳機按住 0.1–0.4 秒，所以右鍵只晚一點點。
- 狀態面板：控制中時，主螢幕右上角（選單列下方）顯示目前模式與可用手勢：指向、按住（拖曳）、兩指捲動、縮放。待命時隱藏。

## M2：點擊與拖曳

控制中（光圈持續發光）時：

- 游標跟著食指第二關節（PIP），不是指尖。手指懸空的輕微抖動不會讓游標動；慢慢移動時游標移動得比較少，方便對準小目標；快速移動時恢復正常，游標也會回到手指對應的位置。
- 點擊（按鍵）：食指伸直，只彎指尖兩節往下按再伸直，像按按鈕；指根與手掌不要動。游標停在開始按之前指著的位置，點擊落在那裡；伸直後約 0.25 秒，或手一移動，游標就恢復跟隨。
- 拖曳：按下後不放約 0.5 秒，再移動手；伸直食指就放下。
- 右鍵（扳機）：食指伸直、拇指豎起（比手槍），拇指往下壓到食指側面再抬起，抬起時送出。點在拇指開始動之前指著的位置。手在移動時不算。
- 捲動（甩動）：食指與中指一起伸直，游標停住，光圈裡出現兩根小手指。指尖往下快速一甩（彎手指），內容往下捲（看到上面的內容）；往上快速一甩（抬手），內容往上捲（看到下面的內容），同觸控板的自然捲動。像在觸控板上甩一下：甩得越快捲得越快，之後逐漸減速，約 2 秒停下；連續甩就一直捲。捲動時小手指往內容移動的方向滑。慢慢收回來不捲；甩完 1.2 秒內往反方向的動作都當成收回（包括甩之前先彎一下手指的預備動作），要換方向先停一下。收回中指（只留食指）就停止，游標恢復跟隨。
- ESC：兩指捲動時做一次扳機。同右鍵，手在動時不算（例如往上甩時抬手，拇指跟著晃）。捲動時拇指不要抬起再放下，否則會按到 ESC。
- 相機使用 1:1 的畫面（內建鏡頭上是 1552×1552），比 16:9 多看到下方，手可以放低一點。換了相機格式或校準方式後會自動要求重新校準；請在平常做手勢的高度校準。

## M1：游標控制

選單列 App：喚醒後伸出食指，游標跟著食指尖移動。

### 建置與執行

```sh
scripts/build-app.sh
open build/Mirage.app
```

- 第一次開啟會詢問相機權限，並提示到 System Settings → Privacy & Security → Accessibility 打開 Mirage（移動游標需要）。
- 鑰匙圈有 Developer ID Application 或 Apple Development 憑證時，會自動用它簽章，重新建置後權限仍有效；第一次簽章可能跳出鑰匙圈存取提示，輸入登入密碼後按 Always Allow。可用 `MIRAGE_SIGN_IDENTITY` 指定憑證。
- 沒有憑證時是 ad-hoc 簽章，每次重新建置後系統都當成新的 App：要在 Accessibility 清單用「−」移除舊的 Mirage 再重新允許。
- build 號是建置時間（例如 `20261001.192045`），顯示在選單底部，可以確認執行的是新版。

### 使用

1. 第一次開啟會先校準：伸出食指、指尖朝上，其他手指收起；倒數 3 秒後，在舒適的範圍內慢慢畫大圈約 4 秒。校準視窗會即時提示看不看得到手、姿勢對不對。之後可從選單列圖示選「重新校準」。
2. 喚醒：張手 → 握拳（各停約 0.3 秒），游標周圍出現閃爍的光圈。
3. 3 秒內伸出食指，光圈變成持續發光，游標開始跟著食指尖移動。手超出畫圈的範圍時，游標停在螢幕邊緣。
4. 手放下超過 2 秒，或離開畫圈範圍（再往外約半個範圍）超過 1 秒，就停止控制，要重新喚醒。
5. `⌃⌥⌘M` 隨時停用或重新啟用，停用時關閉鏡頭。螢幕鎖定、螢幕保護程式、睡眠時自動暫停。
6. 耗電：啟用中鏡頭一直開著。待命（還沒喚醒）時手部偵測降到約 10 fps（每 3 幀處理 1 幀，`FrameThrottle`），喚醒後（光圈閃爍、控制中）恢復每幀都處理。實測（2026-10-01，MacBook 內建鏡頭、待命、沒做手勢）：降速前穩定約 18–28% 單核 CPU（`top` 的 POWER 也是 18–28），降速後約 11–14%；剩下的主要是相機仍以 30 fps 送幀。錄影中偵測每幀 p50 約 20–26 ms。不用的時候用 `⌃⌥⌘M` 停用，或結束 Mirage。

選單列圖示：沙漏 = 正在啟動相機；警告三角形 = 相機無法使用（原因在選單第一行）；斜線的手 = 停用、暫停或尚未校準；準星 = 校準中；空心的手 = 待命；實心的手 = 已喚醒；指向的手 = 控制中。

## M0：可行性驗證

在 MacBook 內建鏡頭上量測 Apple Vision 手部追蹤的延遲、抖動與偵測率，並確認捏合與「張手 → 握拳」能否穩定辨識，作為要不要改用 MediaPipe 的依據。這個階段不會控制游標。

M0.1 追加：

- 啟動時列出系統視訊效果（人物置中、人像、攝影棚燈光等）的狀態，並關閉人物置中：它會移動裁切範圍，讓手的座標跟著跳。
- 延遲比較階段輪流使用 4 種設定：A 1280×720、B 640×480、C 只偵測一隻手、D 重測 A（檢查延遲是否隨時間漂移）。
- 點擊與喚醒加上閘門：手的大小要接近靜止階段量到的基準；點擊時食指不能彎；喚醒要張手、握拳各維持 0.3 秒。

M0.2 追加（依 M0.1 結果調整）：

- 640×480 與只偵測一隻手都沒有明顯降低延遲，因此固定 1280×720、偵測兩隻手。延遲比較改為比較推論方式：A 同步（在影格回呼裡推論，M0 與 M0.1 的做法）、B 非同步（回呼立刻返回，推論忙碌時只保留最新一幀）、C、D 依序重測 A、B。其他階段使用非同步。
- 延遲拆出「送達」：影格擷取 → 送達 App 的時間，用來分辨延遲來自相機管線還是推論。
- 捏合閾值放寬為 0.30 / 0.45；點擊的第二幀必須實際量到捏合，開始捏合的前一幀也必須量得到（手剛入鏡時的捏合不算）。捏合時拇指常擋住食指根部關節，掌寬量不到時沿用 0.2 秒內最近一次量到的值。
- 喚醒容忍張手到握拳之間最多 0.3 秒的過渡姿勢：手指收攏時會經過幾幀既不是張手也不是握拳的姿勢。

### 執行

需要 macOS 26 與 Xcode 26（或對應的 Command Line Tools）。

```sh
swift run -c release mirage-spike
```

- 第一次執行時，系統會詢問你用來執行的終端機 App 能否使用相機。
- 視窗與終端機會依序提示各階段：手入鏡 1 秒後開始，每個階段先顯示說明 5 秒、倒數 3、2、1 才開始記錄，共約 130 秒，照做即可；關閉視窗會提前結束。
- 視窗只畫手部骨架，不顯示相機畫面。藍框是假設的感應區，白色圓圈是濾波後的游標，捏合時會填滿。

錄其他手勢改用 `gestures` 腳本（扳機、兩指扳機、半彎捲動、反向捲動、握拳、日常）或 `precision` 腳本（懸停、慢速對準、快速移動、按鍵點擊與按住等）；`--format 寬x高` 可指定相機格式，預設同 App：

```sh
swift run -c release mirage-spike gestures --format 1552x1552
```

`gaze` 腳本評估眼動追蹤是否可行（不整合進 App）：視窗全螢幕，臉入鏡 1 秒後開始，依序看 3×3 的黃點（校準、換順序驗證、轉頭各一輪），最後比較只偵測手、手與臉都偵測時手的延遲。紀錄預設只存眼睛輪廓、瞳孔、頭部角度與臉框的座標，不存影像。摘要列出用 9 點校準後估計注視位置的誤差：

```sh
swift run -c release mirage-spike gaze
```

加 `--frames` 會在注視階段每約 0.1 秒把相機影像存成 JPEG，放在 `recordings/gaze-<時間>/frames/`（路徑記在紀錄的 `image` 欄位），供離線比較其他注視模型。影像含臉部，只存在本機，`recordings/` 不進版控。

```sh
swift run -c release mirage-spike gaze --frames
```

全螢幕視窗與目標點放在目前的主要視窗所在的螢幕，接外接螢幕時可能不是內建的；開始時會印出「螢幕：名稱 寬×高 pt」。加 `--builtin` 固定用內建螢幕（App 控制的也是內建螢幕）。

眼動的結果（2026-09-28、09-29）：不可行，不整合進 App。用 `--frames` 存下影像後，在同一份錄影上比較了三種方法（`tools/gaze-spike/`）。
- 條件：單一受測者（戴眼鏡）、9 點校準，每種螢幕各一份錄影；誤差為 p50 / p90（pt）。粗定位（眼睛選大概位置、手細調）的通過標準是 p50 ≤ 250、p90 ≤ 450。
- 09-28 與 09-29 第一份是在外接 1920×1080 螢幕上錄的（當時工具把視窗放在主要視窗所在的螢幕）；09-29 第二份才是內建 1728×1117，也就是 App 控制的螢幕。

| 方法 | 外接：換順序驗證 | 外接：轉頭 | 內建：換順序驗證 | 內建：轉頭 |
|---|---|---|---|---|
| 永遠猜中央 | 768 / 881 | — | 691 / 823 | — |
| Vision 瞳孔（二次） | 259 / 819 | 388 / 836 | 432 / 1121 | 526 / 924 |
| MediaPipe 虹膜（二次） | 330 / 688 | 380 / 753 | 686 / 946 | 623 / 825 |
| CNN 視線角度（一次） | 113 / 560 | 146 / 376 | 395 / 1016 | 427 / 651 |
| CNN 視線向量（二次） | 249 / 476 | 265 / 405 | 366 / 1185 | 420 / 821 |

- 外接螢幕：CNN（ptgaze 的 MPIIFaceGaze ResNet）接近標準，轉頭階段通過，換順序驗證的 p90 超過。內建螢幕都不通過：CNN 各種組合的 p50 在 338 以上、p90 在 625 以上。
- 訊號：「水平訊號比」是螢幕左右 10%→90% 的平均變化除以同一目標內的逐幀標準差。Vision 瞳孔外接 9.4×、內建 1.9×（09-28 那份幾乎是 0）；CNN 外接 15×、內建 3.2×。內建的垂直方向幾乎沒有訊號（CNN 0.9×、瞳孔 0.4×）。同樣涵蓋 80% 螢幕寬度，CNN 估計的水平視線角度外接 23.8°、內建 6.9°。
- 平滑 0.3–1.0 秒沒有改善，誤差是系統性的；假設的相機焦距在 900–3000 px 之間，結果差不多。
- 內建為什麼差：沒有確認。錄影中頭部朝向的水平量，從螢幕左到右轉了約 18°（外接約 9°），推測是靠轉頭看、眼睛轉得少；但每種螢幕只有一份錄影，不能排除只是那次的姿勢。
- MediaPipe Face Landmarker 的眼神 blendshape、頭部姿態矩陣，沒有哪個組合在兩種螢幕上都穩定地比虹膜好；內建螢幕上預測落在正確欄的比例，多數組合接近隨機（33%），最好的 50%。
- 更正：09-28 的評估中，Vision 回傳的頭部角度沒有資訊（yaw 只有 0 與 −45°，roll 只有 0 與 −30°，pitch 沒有值），所以當時的「只看頭」與「眼睛＋頭」實際只用臉在畫面中的位置。
- 延遲：加上臉部偵測後，手的延遲 p95 多約 60 ms；09-29 的錄影中，手的幀率從約 29 降到 15 fps。

### 指標

| 指標 | 意義 | 參考目標 |
|---|---|---|
| 延遲 p50/p95 | 影格擷取 → 推論完成；括號內是其中送達 App 與推論各花多少；延遲比較階段分推論方式列出 | p95 < 50 ms |
| 逐幀跳動 p50/p95 | 靜止時游標每幀移動的距離（螢幕 pt），原始 vs 濾波後 | 濾波後 p95 < 3 pt |
| 偵測率 | 偵測到食指尖的幀比例 | 靜止、移動 > 95% |
| 濾波延遲 | 濾波後游標落後原始位置的時間 | < 30 ms |
| 點擊 | 捏合階段確認的點擊次數；p5/p95 是捏合比例分布，兩者差越大越好分辨 | 10 |
| 喚醒 | 喚醒階段偵測到的張手 → 握拳次數 | 5 |
| 誤觸 | 日常階段的點擊與喚醒次數 | 0 |
