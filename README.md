# Mirage

在 MacBook 鏡頭前以單手手勢操控游標、點擊、捲動與縮放的 macOS App（macOS 26+）。

## M2：點擊與拖曳

控制中（光圈持續發光）時：

- 點擊：拇指與食指快速捏一下再放開。游標停在捏合前指著的位置，點擊落在那裡；手指張開後游標才恢復跟隨。
- 拖曳：捏住不放約 0.5 秒後移動手，張開手指就放下。
- 捲動：食指與中指一起伸直，游標停住，光圈裡出現兩根往下滑的小手指。手不用動，兩指往下彎一下，頁面內容就往下移一段（看到上面的內容），伸直回來不捲；彎得快會再慣性捲動一下。要看下面的內容：彎著停約 1 秒，小手指改成往上滑，之後每伸直一下，內容往上移一段；伸直停約 1 秒就換回來。收回中指（只留食指）就停止，游標恢復跟隨。
- 右鍵：食指與中指伸直時，拇指快速捏一下食指（同觸控板的兩指點按）。彎成拳頭時拇指碰到食指不算。

## M1：游標控制

選單列 App：喚醒後伸出食指，游標跟著食指尖移動。

### 建置與執行

```sh
scripts/build-app.sh
open build/Mirage.app
```

- 第一次開啟會詢問相機權限，並提示到 System Settings → Privacy & Security → Accessibility 打開 Mirage（移動游標需要）。
- 鑰匙圈有 Developer ID Application 或 Apple Development 憑證時，會自動用它簽章，重新建置後權限仍有效；第一次簽章可能跳出鑰匙圈存取提示，輸入登入密碼後按 Always Allow。可用 `MIRAGE_SIGN_IDENTITY` 指定憑證。
- 沒有憑證時是 ad-hoc 簽章，每次重新建置後系統都當成新的 App：要在 Accessibility 清單用「−」移除舊的 Mirage 再重新允許。

### 使用

1. 第一次開啟會先校準：伸出食指、指尖朝上，其他手指收起；倒數 3 秒後，在舒適的範圍內慢慢畫大圈約 4 秒。校準視窗會即時提示看不看得到手、姿勢對不對。之後可從選單列圖示選「重新校準」。
2. 喚醒：張手 → 握拳（各停約 0.3 秒），游標周圍出現閃爍的光圈。
3. 3 秒內伸出食指，光圈變成持續發光，游標開始跟著食指尖移動。手超出畫圈的範圍時，游標停在螢幕邊緣。
4. 手放下超過 2 秒，或離開畫圈範圍（再往外約半個範圍）超過 1 秒，就停止控制，要重新喚醒。
5. `⌃⌥⌘M` 隨時停用或重新啟用，停用時關閉鏡頭。螢幕鎖定、螢幕保護程式、睡眠時自動暫停。

選單列圖示：沙漏 = 正在啟動相機；警告三角形 = 相機無法使用（原因在選單第一行）；斜線的手 = 停用、暫停或尚未校準；準星 = 校準中；空心的手 = 待命；實心的手 = 已喚醒；指向的手 = 控制中。

## M0：可行性驗證

在 MacBook 內建鏡頭上量測 Apple Vision 手部追蹤的延遲、抖動與偵測率，並確認捏合與「張手 → 握拳」能否穩定辨識，作為要不要改用 MediaPipe 的依據。這個階段不會控制游標。

M0.1 追加：

- 啟動時列出系統視訊效果（人物置中、人像、攝影棚燈光等）的狀態，並關閉人物置中：它會移動裁切範圍，讓手的座標跟著跳。
- 延遲比較階段輪流使用 4 種設定：A 1280×720、B 640×480、C 只偵測一隻手、D 重測 A（檢查延遲是否隨時間漂移）。
- 點擊與喚醒加上閘門：手的大小要接近靜止階段量到的基準；點擊時食指不能彎；喚醒要張手、握拳各維持 0.3 秒。

M0.2 追加（依 M0.1 結果調整）：

- 640×480 與只偵測一隻手都沒有明顯降低延遲，因此固定 1280×720、偵測兩隻手。延遲比較改為比較推論方式：A 同步（在影格回呼裡推論，M0 與 M0.1 的做法）、B 非同步（回呼立刻返回，推論忙碌時只保留最新一幀）、C、D 依序重測 A、B。其他階段使用非同步。
- 延遲拆出「送達」：影格擷取 → 送達 App 的時間，用來分辨延遲來自相機管線還是推論。
- 捏合閾值放寬為 0.30 / 0.45；點擊的第二幀必須實際量到捏合，開始捏合的前一幀也必須量得到（手剛入鏡時的捏合不算）。捏合時拇指常擋住食指根部關節，掌寬量不到時沿用 0.2 秒內最近一次量到的值。
- 喚醒容忍張手到握拳之間最多 0.3 秒的過渡姿勢：手指收攏時會經過幾幀既不是張手也不是握拳的姿勢。

### 執行

需要 macOS 26 與 Xcode 26（或對應的 Command Line Tools）。

```sh
swift run -c release mirage-spike
```

- 第一次執行時，系統會詢問你用來執行的終端機 App 能否使用相機。
- 視窗與終端機會依序提示各階段：手入鏡 1 秒後開始計時，之後共約 82 秒，照做即可；關閉視窗會提前結束。
- 視窗只畫手部骨架，不顯示相機畫面。藍框是假設的感應區，白色圓圈是濾波後的游標，捏合時會填滿。

結束後終端機會印出結果，並在 `recordings/` 產生兩個檔案：

- `m0-<時間>.txt`：結果摘要。
- `m0-<時間>.jsonl`：每幀 21 個關節的座標，之後用來離線調參數與重播測試手勢。

### 指標

| 指標 | 意義 | 參考目標 |
|---|---|---|
| 延遲 p50/p95 | 影格擷取 → 推論完成；括號內是其中送達 App 與推論各花多少；延遲比較階段分推論方式列出 | p95 < 50 ms |
| 逐幀跳動 p50/p95 | 靜止時游標每幀移動的距離（螢幕 pt），原始 vs 濾波後 | 濾波後 p95 < 3 pt |
| 偵測率 | 偵測到食指尖的幀比例 | 靜止、移動 > 95% |
| 濾波延遲 | 濾波後游標落後原始位置的時間 | < 30 ms |
| 點擊 | 捏合階段確認的點擊次數；p5/p95 是捏合比例分布，兩者差越大越好分辨 | 10 |
| 喚醒 | 喚醒階段偵測到的張手 → 握拳次數 | 5 |
| 誤觸 | 日常階段的點擊與喚醒次數 | 0 |
