# Mirage

在 MacBook 鏡頭前以單手手勢操控游標、點擊、捲動與縮放的 macOS App（macOS 26+）。

## M3：操作者鎖定、縮放與狀態面板

- 操作者鎖定：喚醒後只跟著喚醒的那隻手，依連續性判斷（每一幀取離上一幀最近、2.5 個掌寬以內的手）。旁人的手或自己的另一隻手在畫面別處出現都不影響；操作者的手離開超過 2 秒就停止控制，要重新喚醒。
- 縮放：扳機按住不放約 0.5 秒，游標停住；之後手往上移放大、往下移縮小，每移約 150 pt 送一次 ⌘= 或 ⌘−（瀏覽器、Finder、預覽程式等都適用）。放開拇指就結束，不會送右鍵。
- 右鍵改成拇指抬起時才送出，按住超過 0.5 秒就是縮放。一般的扳機按住 0.1–0.4 秒，所以右鍵只晚一點點。
- 狀態面板：控制中時，主螢幕右上角（選單列下方）顯示目前模式與可用手勢：指向、按住（拖曳）、兩指／三指捲動、縮放。待命時隱藏。

## M2：點擊與拖曳

控制中（光圈持續發光）時：

- 游標跟著食指第二關節（PIP），不是指尖。手指懸空的輕微抖動不會讓游標動；慢慢移動時游標移動得比較少，方便對準小目標；快速移動時恢復正常，游標也會回到手指對應的位置。
- 點擊（按鍵）：食指伸直，只彎指尖兩節往下按再伸直，像按按鈕；指根與手掌不要動。游標停在開始按之前指著的位置，點擊落在那裡；伸直後約 0.25 秒，或手一移動，游標就恢復跟隨。
- 拖曳：按下後不放約 0.5 秒，再移動手；伸直食指就放下。
- 右鍵（扳機）：食指伸直、拇指豎起（比手槍），拇指往下壓到食指側面再抬起，抬起時送出。點在拇指開始動之前指著的位置。手在移動時不算。
- 捲動：食指與中指一起伸直，游標停住，光圈裡出現兩根往下滑的小手指。手不用動，兩指往下彎一下（彎一半就可以），頁面內容就往下移一段（看到上面的內容），伸直回來不捲；彎得快會再慣性捲動一下。要看下面的內容：改成食指、中指、無名指三指伸直（小指收起），光圈裡變成三根往上滑的小手指，之後每彎一下，內容往上移一段。收回中指（只留食指）就停止，游標恢復跟隨。
- ESC：兩指（或三指）捲動時做一次扳機。捲動時拇指不要抬起再放下，否則會按到 ESC。
- 相機使用 1:1 的畫面（內建鏡頭上是 1552×1552），比 16:9 多看到下方，手可以放低一點。換了相機格式或校準方式後會自動要求重新校準；請在平常做手勢的高度校準。

## M1：游標控制

選單列 App：喚醒後伸出食指，游標跟著食指尖移動。

### 建置與執行

```sh
scripts/build-app.sh
open build/Mirage.app
```

- 第一次開啟會詢問相機權限，並提示到 System Settings → Privacy & Security → Accessibility 打開 Mirage（移動游標需要）。
- 鑰匙圈有 Developer ID Application 或 Apple Development 憑證時，會自動用它簽章，重新建置後權限仍有效；第一次簽章可能跳出鑰匙圈存取提示，輸入登入密碼後按 Always Allow。可用 `MIRAGE_SIGN_IDENTITY` 指定憑證。
- 沒有憑證時是 ad-hoc 簽章，每次重新建置後系統都當成新的 App：要在 Accessibility 清單用「−」移除舊的 Mirage 再重新允許。

### 使用

1. 第一次開啟會先校準：伸出食指、指尖朝上，其他手指收起；倒數 3 秒後，在舒適的範圍內慢慢畫大圈約 4 秒。校準視窗會即時提示看不看得到手、姿勢對不對。之後可從選單列圖示選「重新校準」。
2. 喚醒：張手 → 握拳（各停約 0.3 秒），游標周圍出現閃爍的光圈。
3. 3 秒內伸出食指，光圈變成持續發光，游標開始跟著食指尖移動。手超出畫圈的範圍時，游標停在螢幕邊緣。
4. 手放下超過 2 秒，或離開畫圈範圍（再往外約半個範圍）超過 1 秒，就停止控制，要重新喚醒。
5. `⌃⌥⌘M` 隨時停用或重新啟用，停用時關閉鏡頭。螢幕鎖定、螢幕保護程式、睡眠時自動暫停。

選單列圖示：沙漏 = 正在啟動相機；警告三角形 = 相機無法使用（原因在選單第一行）；斜線的手 = 停用、暫停或尚未校準；準星 = 校準中；空心的手 = 待命；實心的手 = 已喚醒；指向的手 = 控制中。

## M0：可行性驗證

在 MacBook 內建鏡頭上量測 Apple Vision 手部追蹤的延遲、抖動與偵測率，並確認捏合與「張手 → 握拳」能否穩定辨識，作為要不要改用 MediaPipe 的依據。這個階段不會控制游標。

M0.1 追加：

- 啟動時列出系統視訊效果（人物置中、人像、攝影棚燈光等）的狀態，並關閉人物置中：它會移動裁切範圍，讓手的座標跟著跳。
- 延遲比較階段輪流使用 4 種設定：A 1280×720、B 640×480、C 只偵測一隻手、D 重測 A（檢查延遲是否隨時間漂移）。
- 點擊與喚醒加上閘門：手的大小要接近靜止階段量到的基準；點擊時食指不能彎；喚醒要張手、握拳各維持 0.3 秒。

M0.2 追加（依 M0.1 結果調整）：

- 640×480 與只偵測一隻手都沒有明顯降低延遲，因此固定 1280×720、偵測兩隻手。延遲比較改為比較推論方式：A 同步（在影格回呼裡推論，M0 與 M0.1 的做法）、B 非同步（回呼立刻返回，推論忙碌時只保留最新一幀）、C、D 依序重測 A、B。其他階段使用非同步。
- 延遲拆出「送達」：影格擷取 → 送達 App 的時間，用來分辨延遲來自相機管線還是推論。
- 捏合閾值放寬為 0.30 / 0.45；點擊的第二幀必須實際量到捏合，開始捏合的前一幀也必須量得到（手剛入鏡時的捏合不算）。捏合時拇指常擋住食指根部關節，掌寬量不到時沿用 0.2 秒內最近一次量到的值。
- 喚醒容忍張手到握拳之間最多 0.3 秒的過渡姿勢：手指收攏時會經過幾幀既不是張手也不是握拳的姿勢。

### 執行

需要 macOS 26 與 Xcode 26（或對應的 Command Line Tools）。

```sh
swift run -c release mirage-spike
```

- 第一次執行時，系統會詢問你用來執行的終端機 App 能否使用相機。
- 視窗與終端機會依序提示各階段：手入鏡 1 秒後開始，每個階段先顯示說明 5 秒、倒數 3、2、1 才開始記錄，共約 130 秒，照做即可；關閉視窗會提前結束。
- 視窗只畫手部骨架，不顯示相機畫面。藍框是假設的感應區，白色圓圈是濾波後的游標，捏合時會填滿。

錄其他手勢改用 `gestures` 腳本（扳機、兩指扳機、半彎捲動、反向捲動、握拳、日常）或 `precision` 腳本（懸停、慢速對準、快速移動、按鍵點擊與按住等）；`--format 寬x高` 可指定相機格式，預設同 App：

```sh
swift run -c release mirage-spike gestures --format 1552x1552
```

`gaze` 腳本評估眼動追蹤是否可行（不整合進 App）：視窗全螢幕，臉入鏡 1 秒後開始，依序看 3×3 的黃點（校準、換順序驗證、轉頭各一輪），最後比較只偵測手、手與臉都偵測時手的延遲。紀錄只存眼睛輪廓、瞳孔、頭部角度與臉框的座標，不存影像。摘要列出用 9 點校準後估計注視位置的誤差：

```sh
swift run -c release mirage-spike gaze
```

2026-09-28 的結果：不可行，不整合進 App。
- 誤差：9 點校準後估計注視位置，p50 330–580 pt、p90 690–890 pt；永遠猜螢幕中央是 768 / 881 pt。
- 原因：看完整個螢幕寬度，瞳孔在眼角之間只移動約 5 px，Vision 的瞳孔點逐幀就晃 0.7–2 px。
- 延遲：加上臉部偵測後，手的延遲 p95 多約 60 ms。

`depth` 腳本評估只用 2D 關節推估深度（2.5D）有沒有幫助。它錄按鍵、往前戳（整根食指往螢幕戳），並對照懸停、快速移動、日常：

```sh
swift run -c release mirage-spike depth
```

2026-09-28 的結果：沒有幫助，沒有整合。「訊雜比」是上升量除以懸停時的 p99，≥ 3 才分得開。
- 按鍵：3D 彎曲估計的訊雜比 1.5–8.5×，不比 2D 彎曲（7.0–8.8×）好。
- 往前戳：3D 彎曲估計 1.3×、指尖前縮 2.0×、整手靠近 1.7×，都分不開。
- 原因：用長度比推估出平面角會放大關節的晃動；手指接近平貼畫面時，角度最不穩。
- 現行的 2D 按鍵偵測在同一份錄影中，按鍵 10/10、往前戳 9/10 都算左鍵，其他階段沒有誤觸。手放低時往前戳在畫面上看起來就是彎手指。

`tools/mediapipe-spike/` 用 MediaPipe HandLandmarker（單眼 3D 手部模型）錄同樣的階段，比較同一個模型的 2D 與 3D 特徵。第一次使用前要先建虛擬環境：Mac 版 mediapipe 只在公開 PyPI 上有，而且 Mac 上要用 GPU 模式。

```sh
cd tools/mediapipe-spike
/opt/homebrew/bin/python3.12 -m venv .venv
.venv/bin/pip install --index-url https://pypi.org/simple mediapipe
curl -sSLO https://storage.googleapis.com/mediapipe-models/hand_landmarker/hand_landmarker/float16/latest/hand_landmarker.task
.venv/bin/python record.py
```

- 錄完會印出評估結果，紀錄存在 `recordings/mediapipe-depth-<時間>.jsonl`。
- 之後可以用 `.venv/bin/python analyze.py <紀錄>` 重新分析。

2026-09-28 的結果：不通過，放棄。「訊雜比」同上，是上升量除以懸停時的 p99。
- 按鍵：3D 特徵的訊雜比最多 2.1×（指尖往鏡頭的深度），不如同一個模型的 2D 彎曲（5.8×）。用 3D 座標算的彎曲角只有 1.1×。
- 往前戳：指尖往鏡頭 2.5×，和 2D 的 2.4× 差不多。而且快速移動時的深度晃動（p99 26 mm）比往前戳本身（17 mm）還大，會誤觸。
- 推論很快，p50 / p95 為 8.9 / 12.8 ms。但透過 OpenCV 擷取時，鏡頭在光線不足下自動降到 15 fps；這不影響上面的結論。

結束後終端機會印出結果，並在 `recordings/` 產生兩個檔案：

- `<腳本>-<時間>.txt`（`m0` 或 `gestures`）：結果摘要。
- `<腳本>-<時間>.jsonl`：每幀 21 個關節的座標，之後用來離線調參數與重播測試手勢（`RecordingReplayTests`）。

### 指標

| 指標 | 意義 | 參考目標 |
|---|---|---|
| 延遲 p50/p95 | 影格擷取 → 推論完成；括號內是其中送達 App 與推論各花多少；延遲比較階段分推論方式列出 | p95 < 50 ms |
| 逐幀跳動 p50/p95 | 靜止時游標每幀移動的距離（螢幕 pt），原始 vs 濾波後 | 濾波後 p95 < 3 pt |
| 偵測率 | 偵測到食指尖的幀比例 | 靜止、移動 > 95% |
| 濾波延遲 | 濾波後游標落後原始位置的時間 | < 30 ms |
| 點擊 | 捏合階段確認的點擊次數；p5/p95 是捏合比例分布，兩者差越大越好分辨 | 10 |
| 喚醒 | 喚醒階段偵測到的張手 → 握拳次數 | 5 |
| 誤觸 | 日常階段的點擊與喚醒次數 | 0 |
